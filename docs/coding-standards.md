# Coding Standards

Project-wide coding conventions.

## General

- Follow existing patterns in the codebase before introducing new ones.
- Keep code simple and readable; favor clarity over cleverness.
- Do not add comments unless they explain non-obvious intent.
- Refactor unrelated code
- Modify tests just to make them pass.
- Prefer the smallest correct change.

## Commits

- Write concise commit messages that match the repo style.
- Only commit when explicitly asked.

## Verification

- Run lint and typecheck commands when the project provides them.
- Never assume a test framework; check the README or existing config.
